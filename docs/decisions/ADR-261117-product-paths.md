# ADR-261117-product-paths: 제품 경로를 프로젝트가 선언한다 — work.product

- 상태: Proposed (REP `rep/product-paths` — PR 리뷰·병합이 승인이다)
- 작성: Claude Code (claude-fable-5-2) · 담당 mathjjang · 2026-11-17
- 강제 등급: gate — 집행 수단: `.harness/catalog.yaml` check-branch-record.mjs(pre-commit) · ci.mjs(PR) · lint ⑲ · guard-scratch(쓰기 전 훅) · setup.mjs(설정 질문 Q8)
- 위험: medium (제품 경로 판정 — 모든 게이트가 쓰는 기준. 선언하지 않은 프로젝트의 동작은 그대로)
- 선행 RFC: 없음
- 관련: HARNESS §8 · §11 · runbooks/work.md · runbooks/init.md
- 정책 소유: technical

> ADR은 되돌리기 비싼 결정에만 쓴다. 결정은 단정문으로. 대안이 비면 "정말 비교했나"를 의심한다.

## 1. Context (왜 지금)

제품 경로는 "문서·규칙·목업·장치 폴더와 등재한 루트 파일이 아닌 것 전부"였다. 문서 폴더 목록이 코드에 고정돼 있어서, 프로젝트가 소스가 아닌 폴더를 하나 두면 그 폴더는 제품 경로가 된다. 사람이 읽고 판단하는 문서 폴더(예: 물려받은 코드의 결함을 적어 두고 고칠지 말지부터 정하는 자리)의 메모 한 줄을 고치는 데 FDR·worktree·리뷰가 필요했다. 루트 파일은 `work.root_files`로 등재할 수 있지만 폴더에는 그런 설정이 없었다.

소스가 한 폴더에 모여 있는 프로젝트(물려받은 코드를 폴더째 들여온 경우 등)는 "어디가 소스인가"를 한 줄로 말할 수 있다. 그 답을 프로젝트가 선언하게 하면 게이트는 소스에만 걸리고 나머지는 자유롭다.

## 2. Decision (무엇을 한다 / 하지 않는다)

- `harness.yaml` `work.product`에 소스 위치를 glob 목록으로 선언할 수 있다. 선언하면 **그 경로만 제품 경로다** — main 직접 커밋 금지·FDR scope·판정 뒤 코드 변경(⑧)이 그 경로에만 걸린다. 나머지는 폴더를 새로 만들어도 main에 바로 커밋한다.
- 선언하지 않으면(`product: []`) 지금까지와 같다 — 문서·규칙·목업·장치 폴더와 등재한 루트 파일 밖 전부가 제품 경로다.
- 값은 프로젝트 설정 질문 Q8("실제 소스 코드가 있는 위치")의 답이다. 에이전트는 설정 때 이것을 묻는다(runbooks/init.md 반드시 묻는 것). 답은 `harness.yaml` `work.product`와 setup 블록, 프로젝트 설정 ADR에 남는다. 나중에 바꾸는 것은 ADR이다.
- 쓸 수 없는 항목(빈 값 · 절대 경로 · `..` · 역슬래시 · 문서/규칙/장치 폴더)은 버린다. 남는 항목이 없으면 선언하지 않은 것으로 본다 — 닫힌 쪽으로 실패한다. lint ⑲가 그런 항목을 알린다.
- PR 판정(ci)과 ff 병합 전 리뷰 하한(work.mjs)은 base 쪽 `work.product`로 본다 — PR이 스스로 좁힌 선언은 그 PR에서 효력이 없다(`work.root_files`와 같은 규칙).
- `work.product`를 선언한 프로젝트에서는 쓰기 전 훅(guard-scratch)이 루트의 새 항목을 막지 않는다. 임시 패턴 이름(`.tmp*`·`*.log`·`probe-*` …)과 `docs/`·`rules/`의 고정 폴더 규칙은 그대로다.
- 하지 않는 것: `docs/` 여덟 폴더·기록 자리 규칙을 바꾸지 않는다. 제품 경로가 아닌 폴더에 무엇을 둘지(양식·절차)는 정하지 않는다 — 프로젝트 몫이다.

## 3. Alternatives

| 대안 | 장점 | 탈락 사유 |
|---|---|---|
| 문서 폴더를 등재하는 목록(`work.doc_dirs`) | 기본 판정을 안 뒤집음 | 폴더가 생길 때마다 등재해야 한다. "소스가 어디인가"는 한 번 정하면 되는데 "소스가 아닌 것"은 계속 늘어난다 |
| `work.root_files`에 폴더를 허용 | 설정 키가 늘지 않음 | 하위 경로를 넣어 scope·⑧을 끄는 것을 막으려고 파일 이름만 받게 한 설정이다(lint ⑲) |
| 새 폴더를 `docs/` 아래에 두게 하기 | 코드 변경 없음 | `docs/`는 여덟 폴더로 고정이다. 사람이 루트에서 바로 찾는 자리를 원하는 경우를 풀지 못한다 |
| 선언을 필수로(없으면 실패) | 모든 프로젝트가 명시 | 이미 쓰는 프로젝트가 sync-core만으로 깨진다 |

## 4. Consequences (득실 · 후속 작업 · 되돌릴 때 비용)

- 득: 소스 밖의 폴더·파일을 만들고 고치는 데 FDR·worktree가 필요 없다. 게이트의 대상이 "소스"라는 것이 설정 한 줄로 보인다.
- 실: 선언에서 빠진 소스는 게이트를 타지 않는다. 소스 폴더가 늘면 `work.product`를 같이 고쳐야 한다(ADR). 선언한 프로젝트는 루트에 폴더가 쌓여도 훅이 막지 않는다.
- 실: `work.root_files`는 선언한 프로젝트에서 쓰이지 않는다(제품 경로가 아닌 것이 "선언 밖 전부"라서).
- 릴리스 노트: 설정 변경 없음 — sync-core만. 선언하려면 `node .harness/scripts/setup.mjs --interactive --reconfigure`(또는 `--answers`)로 Q8에 답한다. `harness.yaml`에 `product:` 줄이 없는 프로젝트는 setup이 `merge:` 줄 아래에 넣는다.
- 미검증: 실제 프로젝트에 sync-core한 뒤의 재설정 경로(self-test는 임시 저장소에서 처음 설정·재설정을 돈다).
- 되돌릴 때: `work.product`를 비우면 기본 판정으로 돌아간다. 코드를 되돌릴 때는 `nonProduct`의 product 인자와 Q8을 뺀다.
