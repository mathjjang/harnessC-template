# ADR-261113-scope-overlap-after-merge: 제품 변경이 병합된 FDR의 기록 커밋이 scope 겹침으로 막히면 종결 단계로 올린다

- 상태: Accepted
- 작성: Claude Code (claude-opus-5-5) · 2026-11-13
- 강제 등급: runbook — 집행 수단: `.harness/runbooks/work.md` §1 · 판정은 기존 lint ⑭(`shipped|closed|abandoned` 제외 — 코드 변경 없음)
- 위험: low
- 선행 RFC: 없음
- 관련: automation 2026-11-12~13 — FDR-261112-agent-service-http의 제품 PR(제품 저장소)은 병합됐는데, 다른 세션의 열린 기록 PR(in-progress FDR, 충돌로 멈춤)과 scope가 겹쳐 기록 커밋이 하루 가까이 막힘. 사용자 "runbook 규칙에 적용 … 탬플릿에도 반영해야 해"
- 정책 소유: technical

> ADR은 되돌리기 비싼 결정에만 쓴다. 결정은 단정문으로. 대안이 비면 "정말 비교했나"를 의심한다.

## 1. Context (왜 지금)

- lint ⑭는 활성 FDR(draft·in-progress)끼리 scope가 겹치면 커밋을 막는다. 같은 제품 경로를 동시에 고치면 서로 덮어쓰기 때문이다. work.md §1의 처방은 "공유 변경을 lite FDR로 먼저 병합"이다.
- 제품 저장소가 기록 저장소와 따로인 프로젝트에서는 제품 PR이 먼저 병합되고, 기록(스펙 병합·종결)은 그 뒤에 기록 저장소 PR로 간다. 이 사이에 내 FDR이 아직 in-progress로 보이면, 다른 세션의 in-progress FDR과 겹쳐 기록 커밋이 막힌다. 이미 병합된 코드라 덮어쓸 위험이 없는데도 막힌다.
- 이때 "공유분 lite FDR"은 할 일이 없다(공유분은 이미 main에 있다). 상대 세션이 멈춰 있으면 기다리는 것 말고는 길이 없었고, 상대 PR을 대신 고치는 것은 남의 활성 영역을 건드리는 일이다.
- lint ⑭는 이미 `shipped`를 겹침 대상에서 뺀다("이미 main에 병합 — 동시 편집 위험이 없다"). 규칙은 맞는데 그 길이 절차에 적혀 있지 않았다.

## 2. Decision (무엇을 한다 / 하지 않는다)

- 내 FDR의 제품 변경이 병합됐고 기록 커밋만 lint ⑭로 막히면, 내 FDR을 종결 단계로 올린다: 스펙 병합 → 리뷰 판정·사인오프 → `status: shipped` → 07-close → 커밋·finish·병합 → closed.
- 본 트리(main)에 미커밋 기록이 있으면 FDR worktree로 옮긴다. ADR은 FDR 브랜치에서 다른 기록으로 거부되므로 main에 따로 커밋한다.
- 하지 않는다: 스펙 병합 없이 상태만 올리기(겹침을 피하려는 상태 변경). 상대 세션의 PR·브랜치를 rebase·수정·force-push로 정리하기 — 멈춰 있으면 사람에게 보고한다.
- 제품 변경이 아직 병합 전이면 이 결정이 아니다. 기존 처방(공유분 lite FDR)을 따른다.

## 3. Alternatives

| 대안 | 장점 | 탈락 사유 |
|---|---|---|
| 상대 PR이 병합될 때까지 기다린다 | 아무것도 안 바꾼다 | 상대 세션이 멈추면 끝없이 막힌다. 실제로 하루 가까이 막혔다 |
| 상대 PR의 충돌을 대신 풀어 병합한다 | 곧바로 풀린다 | 남의 활성 영역 수정. 상대 로컬 브랜치가 갈라져 있으면 force-push가 필요해진다 |
| lint ⑭를 제품 저장소 병합 여부로 판정 | 자동 | 코어가 제품 저장소 PR 상태를 알아야 한다(네트워크·인증). 지금도 `shipped` 제외로 같은 결과를 낸다 |
| 겹침을 경고로 낮춘다 | 막히지 않는다 | 병합 전 동시 편집 보호가 약해진다 |

## 4. Consequences (득실 · 후속 작업 · 되돌릴 때 비용)

- 득: 제품이 병합된 FDR은 상대 세션 상태와 무관하게 종결할 수 있다. lint·CI 코드는 바뀌지 않는다.
- 실: 절차 한 단락이 늘어난다. 상태만 올리는 오용은 lint가 못 막는다 — 스펙 `last_merge`·07-close를 리뷰·CI가 본다.
- 후속: 프로젝트는 `sync-core`로 받는다. 설정 변경 없음. 같은 내용을 프로젝트 런북으로 먼저 둔 프로젝트(automation `RB-261113-record-commit-scope-overlap`)는 sync 뒤 프로젝트 런북을 지운다.
- 되돌릴 때: work.md §1 단락을 빼면 된다.
