# ADR-261119-start-remote-claim: 착수(work.mjs start)는 원격 브랜치로 점유한다 — 이미 있으면 멈춘다

- 상태: Accepted (REP `rep/start-remote-claim` · 담당 승인 2026-11-19 — 「가능한 방법은 다 쓴다」)
- 작성: Claude Code (claude-fable-5-2) · 담당 mathjjang · 2026-11-19
- 강제 등급: gate — 집행 수단: `.harness/catalog.yaml` work.mjs(start가 origin을 보고 멈추거나 올린다 · self-test 원격 점유 7건)
- 위험: low (원격이 없는 저장소는 그대로다. 원격이 있는 저장소에서 start가 push를 한 번 더 하고, origin에 닿지 못하면 멈춘다 — `--no-claim`으로 예전처럼 시작할 수 있다)
- 선행 RFC: 없음
- 관련: 사고 — 한 프로젝트에서 같은 FDR을 두 PC의 세션이 30분 동안 따로 구현했다(그 프로젝트의 INC-261119-same-fdr-two-sessions)
- 정책 소유: technical

> ADR은 되돌리기 비싼 결정에만 쓴다. 결정은 단정문으로. 대안이 비면 "정말 비교했나"를 의심한다.

## 1. Context (왜 지금)

- 「기록 하나 = 브랜치 하나」가 점유 장치다(`.harness/runbooks/work.md`). 그런데 `start`는 로컬 브랜치와 worktree만 만들었다. 원격을 보지도 올리지도 않아, 그 점유는 첫 push(`finish`) 전까지 그 PC 안에서만 참이었다.
- 두 PC가 같은 기록을 각자 `start`하면 둘 다 통과한다. 겹침은 늦은 쪽의 첫 push가 거부될 때에야 드러난다 — 구현을 얼마나 했든 그 뒤다. lint ⑭는 서로 다른 FDR의 scope 겹침만 본다.

## 2. Decision (무엇을 한다 / 하지 않는다)

- 저장소에 원격 `origin`이 있으면 `work.mjs start <ID>`는:
  1. `git ls-remote --heads origin <type>/<ID>`로 그 브랜치가 원격에 있는지 본다. 닿지 못하면 멈춘다(모르는 채 시작하지 않는다).
  2. 원격에 있고 로컬에 그 브랜치가 없으면 멈춘다 — 「이미 다른 곳에서 착수했다」(마지막 커밋의 사람·시각을 보인다). `--takeover`면 origin 브랜치를 그대로 받아 연다(덮어쓰지 않는다).
  3. 원격에 있고 로컬 브랜치가 그것과 한 줄기(같거나 앞·뒤)면 연다 — 내가 올린 브랜치를 다시 여는 것이다. 갈라져 있으면 멈춘다(두 곳에서 구현했다 — 사람이 정한다).
  4. 원격에 없으면 브랜치를 만들자마자 `push -u`한다. push가 거부되면(그 사이 다른 곳이 올렸다) 방금 만든 worktree·브랜치를 지우고 멈춘다.
- `--no-claim`은 원격을 보지도 올리지도 않는다(오프라인 · 혼자 쓰는 저장소 · 원격이 장애일 때). 원격이 없는 저장소는 플래그 없이도 예전과 같다.
- PR이 없는 종료(ff 병합 · rfc 등 기록만 반입)에서는 `finish`가 원격 점유 브랜치를 지운다 — 남으면 다음 `start`가 「이미 착수」로 읽는다. PR 모드는 그대로다(브랜치는 PR의 head이고 병합 뒤 정리는 저장소 설정·`gc`).
- 하지 않는다: main의 기록 상태(`status`)를 start가 바꾸지 않는다 — 점유의 정본은 원격 브랜치 하나다. 담당이 누구인지(담당표)는 프로젝트가 정한다.

## 3. Alternatives

| 대안 | 장점 | 탈락 사유 |
|---|---|---|
| 그대로 두고 런북에 「start 뒤 push」를 적는다 | 코드 변경 없음 | 규율은 이번 사고를 막지 못했다 — 도구가 해야 한다(HARNESS §10-5) |
| start가 main의 manifest를 in-progress로 고쳐 커밋·push한다 | 다른 PC의 세션 카드에 바로 보인다 | 보호된 main에는 직접 push가 안 된다(`protect`) · 상태 전이가 둘로 갈린다(브랜치의 기록 · main의 사본) |
| 점유 대장 파일(잠금 파일)을 둔다 | 원격 없이도 된다 | work.md의 전제(「점유 대장을 두지 않는다 — 브랜치 이름이 곧 기록」)와 어긋나고, 지우는 것을 잊는다 |
| 원격에 닿지 못하면 경고만 하고 시작한다 | 오프라인에서 안 막힌다 | 겹침을 못 본 채 시작하는 것이 이번 사고다 — 멈추고, 알고서 넘어가는 길(`--no-claim`)을 둔다 |

## 4. Consequences (득실 · 후속 작업 · 되돌릴 때 비용)

- 득: 두 번째 `start`가 구현 0분에 멈춘다. 동시에 눌러도 git의 push 거부가 승부를 가른다.
- 실: start가 네트워크를 탄다(ls-remote · push). 구현 전 브랜치가 원격에 보인다(PR은 아니다).
- 후속: 프로젝트는 `sync-core`로 받는다. 설정 추가는 없다.
- 되돌릴 때 비용: 낮다 — `start`의 한 구획과 `finish`의 한 줄이다.
